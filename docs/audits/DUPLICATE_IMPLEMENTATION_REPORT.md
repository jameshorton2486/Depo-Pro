# Duplicate Implementation Report

Date: 2026-06-26
Branch: feature/stage3-workspace-core

## Purpose

This report identifies places where the same or similar transcript logic exists in more than one runtime path. These duplications are the highest risk areas for drift in a future Wave 22 correction system.

### Duplicate logic

- Editor display path:
  - `buildEditorContent` -> `cfe` -> TipTap nodes
- Export/display text path:
  - `buildTranscriptParagraphs*` -> paragraph rendering

### Evidence

- [src/lib/buildEditorContent.ts:157](C:/Users/james/projects/depo-pro/src/lib/buildEditorContent.ts:157)
- [src/lib/transcript/workspacePresentation.ts:513](C:/Users/james/projects/depo-pro/src/lib/transcript/workspacePresentation.ts:513)

### Risk

- That is acceptable architecturally, but it creates drift risk for any new correction layer unless there is one shared orchestration step before both.

## Highest-Risk Duplications

1. `buildTranscriptParagraphs` vs. `buildTranscriptParagraphsClean`
2. `renderTranscriptParagraphText` vs. `renderTranscriptParagraphTextClean`
3. independent `cfe` invocation across editor, structured display, and export

These are the places where a Wave 22 correction layer should centralize first if the goal is consistency without breaking audio sync.
